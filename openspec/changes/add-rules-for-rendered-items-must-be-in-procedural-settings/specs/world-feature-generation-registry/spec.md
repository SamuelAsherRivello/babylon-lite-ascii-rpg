# Spec Delta

## Purpose

Provides one authoritative, deterministic declaration and registration path for every generated world feature and its procedural setting.

## ADDED Requirements

### Requirement: Declared world-feature generation ownership
Every world-visible feature that can appear during level generation SHALL declare an owner layer, realm scope, generated or on-demand status, placement prerequisites, deterministic distribution data when generated, and rendering/collision identity. A feature that extends an existing owner layer SHALL be registered with that layer's existing generation pass. A feature that introduces a new owner layer SHALL declare a new named pass and explicit insertion prerequisites.

#### Scenario: Generated object joins Object Distribution
- **WHEN** a new object-like feature is declared as level-generated
- **THEN** it SHALL be included in Object Distribution without a separate hard-coded generation path

#### Scenario: Existing layer feature preserves its pass
- **WHEN** a new water depth or civilization feature is declared
- **THEN** it SHALL be generated by the existing Water or Civilization pass respectively and SHALL NOT create a duplicate layer

#### Scenario: New layer declares its placement
- **WHEN** a feature needs a layer not owned by any existing pass
- **THEN** its declaration SHALL identify a unique pass, its prerequisite passes, and the layer data it owns before level generation accepts the feature

### Requirement: Complete procedural-settings registration
Every generated world feature SHALL have a corresponding persisted Procedural settings entry and preview representation, unless its generation behavior is intentionally non-configurable. A non-configurable generated feature SHALL be represented in the ordered catalog without a density selector and SHALL identify its fixed baseline behavior.

#### Scenario: New configurable generated feature appears in settings
- **WHEN** a configurable generated feature is registered
- **THEN** the Procedural catalog and draft preview SHALL include its selected density before a world is regenerated

#### Scenario: New fixed generated feature appears without density control
- **WHEN** a fixed-baseline generated feature is registered
- **THEN** the Procedural catalog SHALL show its ordered pass identity without offering an unsupported density selection

### Requirement: Feature-plan validation
Before a realm is published as playable, the generation plan SHALL reject a generated feature that lacks its required declaration, references an unknown owner layer or prerequisite, has a cyclic dependency, or lacks a required Procedural settings registration. On failure, the system SHALL report the feature identity and missing or invalid declaration.

#### Scenario: Missing generated-feature setting is rejected
- **WHEN** a level-generated feature has no valid Procedural settings registration
- **THEN** level generation SHALL fail before placing that feature and report its identity

#### Scenario: Cyclic prerequisites are rejected
- **WHEN** two or more generated features form a prerequisite cycle
- **THEN** the generation plan SHALL fail before terrain or feature placement begins
