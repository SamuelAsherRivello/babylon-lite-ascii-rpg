# Proposal

## Why

Doors currently communicate only a generic closed/open glyph state, which does
not distinguish a locked doorway from a future non-locked closed doorway and
does not use the supplied item artwork. A consistent locked-door and gold-key
presentation will make the interaction state legible across the generation
preview, world, and HUD.

## What Changes

- Define the Door lifecycle as `locked`, `closed`, and `open`. New generated
  fence and Home doors start locked; `closed` is retained for a later feature
  and is not generated by this change.
- Preserve horizontal and vertical Door orientation for fence layouts, and use
  the front closed/open Door art for Home entrances.
- Render a locked Door as its closed orientation-specific Door plus a separate
  `golden_key.png` overlay. Render a closed Door without that overlay and an
  open Door with its matching open art.
- On a cardinal player action against a locked Door, spend one carried key and
  transition it directly to `open`; without a key it stays locked and blocks
  movement. A closed Door remains blocking and has no unlock transition in
  this change.
- Replace every player-visible key glyph with the supplied gold-key artwork in
  the procedural-generation preview, live world, and character HUD, while
  retaining the existing key pickup and count behavior.

## Capabilities

### New Capabilities

- `static-item-presentation`: renders supplied gold-key art and composed
  locked-Door key overlays consistently across world, preview, and HUD views.

### Modified Capabilities

- `object-spawner-system`: define the explicit Door states and locked-to-open
  key-spend interaction.
- `overworld-buildings`: make Home entrances locked Doors with front-Door
  orientation and the shared Door lifecycle.
- `underground-civilization`: preserve horizontal/vertical fence Door
  orientation while generating locked Door groups.
- `procedural-generation-settings`: show supplied gold-key and locked-Door
  presentation in generation previews.
- `character-info`: replace the key text glyph in the resource cell with the
  supplied gold-key artwork while preserving its count.

## Impact

Affected areas include object state and interaction code, civilization and
Home generation, static-prop/image composition, generation-preview rendering,
and the React character HUD. No new dependencies or public APIs are planned.
